## Project status

The application is implemented in **C++17 / Qt 6 Widgets / CMake**, licensed **GPLv3** (relicensed
from Apache-2.0 because QCustomPlot is GPL). Layout:

- `src/core/` - GUI-free library `advcore`: readers (`VnaReader`, `CsvReader`,
  `FlowTrackerReader` for `.ft`, `FlowTrackerCsvReader` for the CSV export) behind a
  `FormatRegistry`, `ZipArchive` (miniz wrapper), statistics (`FlowStats`), label policy
  (`StatsLabels`), despiking (`Despike`), rotation corrections (`Rotation`), projections
  (`Crs`), surveyed-position import (`GeoPointImport`), point model (`MeasurementPoint`,
  `ProjectModel`, `ProjectSettings` with `Mode`/`CrossSection`), `.advProj` serialization
  (`Project`), xlsx export (`ProfileStatsExport`).
- `src/gui/` - `MainWindow`, `SiteView` (abstract base) with `FlumeView` (lab) and `MapView`
  (field, OSM tiles), `PointWizard`, `ImportWizard`, `FlowTrackerImportWizard`, `CrsDialog`,
  `PlotFrame` (QCustomPlot time series), `ProfileFrame` (vertical profiles + probe alignment),
  `SeriesStyleDialog`, `AboutDialog`.
- `third_party/` - vendored QCustomPlot (GPLv3), KissFFT (BSD) and miniz (MIT); QXlsx (MIT)
  comes via CMake FetchContent (network needed at configure time).
- `tests/tst_core.cpp` - QtTest suite with numeric parity against tke-calculator (reference values
  hardcoded from numpy/pandas runs).
- `tools/make_template.py` - regenerates `templates/ADV-profiles.xlsx`; column order must match
  `statsexport::profileTemplateColumns()` in `src/core/ProfileStatsExport.cpp`.
- `docs/` - Sphinx documentation for Read the Docs (`.readthedocs.yaml` at repo root). Screenshots
  are generated by the app itself: `QT_QPA_PLATFORM=offscreen ./build/adv-explorer --screenshots docs/img`.
- `tests/data/` - sample `.vna` measurement, a FlowTracker2 `.ft` survey with its CSV
  export, and a trimmed GeoPackage, all used by the parity tests.

The original product specification (`instructions.md`) and the Python predecessor codebase
(`tke-calculator-main/`, MATLAB port from Nepf Lab / MIT) were removed after the port was verified;
retrieve them from git history if needed (last present at tag v0.1.2). The predecessor lives at
https://tke-calculator.readthedocs.io/.

## Build and test

```bash
cmake -B build -DCMAKE_BUILD_TYPE=Release   # needs qt6-base-dev qt6-base-dev-tools
cmake --build build -j
ctest --test-dir build --output-on-failure  # runs tests/tst_core
./build/adv-explorer                        # launch the GUI
```

Run a single test function: `./build/tests/tst_core flowStatsParity`.
Windows builds run in CI (`.github/workflows/build.yml`); no cross-compilation.

Python tooling runs in the `adv-explorer` mamba env (numpy, pandas, openpyxl):
`mamba run -n adv-explorer python tools/make_template.py`.

## What the application must do (from the original spec)

ADV-Explorer visualizes and analyzes acoustic Doppler velocimetry (ADV) measurements (Nortek Vectrino,
UBERTONE). Core pieces:

- **Interactive flume frame** (1:5 aspect, light-blue background): top-view where clicking places an
  x-y measurement location. Coordinate origin at center-left inlet: x=0,y=0 there, z=0 at bottom pointing
  up; left bank negative y, right bank positive y; flow left→right. Each x-y location holds one or more
  z-points (circle markers), each with its own data file, water depth (setting depth at an x-y overrides
  it for all points sharing that x-y), and start/end time.
- **Time-series plot frame(s)**: per-point column selection, color-blind-friendly colormaps, configurable
  line/marker style, superposition of multiple points; plus a derived per-file TKE-like fluctuation term
  `0.5*(std(U)² + std(V)² + std(W)²)`.
- **Despiking filters**: linear-interpolation gap fill; correlation threshold (default avg 70); SNR
  threshold (default clean where SNR < 20); velocity threshold (clean where `|comp| > k·std`); the
  Goring & Nikora acceleration/velocity method (ported to `src/core/Despike.cpp`); plus additional
  filters to investigate from https://github.com/farzadasgari/proadv.
- **Vertical profile frame**: z or z/h axis, U/V/W components, stats legend (mean, std, skewness,
  kurtosis, stresses u'v'/u'w'/v'w', TKE, dissipation eps), and **heading/roll/pitch corrections** per
  x-y profile to zero out V and W means (auto-proposed value + manual override) to compensate probe
  misalignment.
- **Exports**: PNG at 300 dpi (as displayed), CSV of shown/corrected columns, per-point and per-profile
  stats (absolute z and relative z/h), including into `templates/ADV-profiles.xlsx` (which also computes
  velocity magnitude and direction).
- **Project files** `.advProj`: self-contained (embed data file contents + all settings) so they open on
  another machine without relative-path breakage.
- **Menus**: File (load/save project), Import (multi-file wizard assigning x,y,z per file), Export
  (Data→csv, Plots→png), Processing (CPU count, capped at available cores), About (license, repo link,
  author/date/version).

## `.vna` file format and coordinate encoding (important domain knowledge)

- `.vna` = whitespace-delimited ASCII table read by `read_vna`. Columns (2 leading throwaway columns
  skipped): `time (s)`, `sample no.`, then per-beam `u/v/w1/w2 (m/s)`, amplitudes (dB), SNR, correlation.
  `.vno` is the paired **binary** original - do not parse it as text.
- **Coordinates are encoded in the file name**: `XX_YY_ZZ_something.vna`, where XX/YY/ZZ are x/y/z in
  **centimeters** (divided by 100 → meters). A leading `__` encodes a negative coordinate (see
  `vna_file_name2coordinates`). The new app instead lets users assign x/y/z interactively, but must still
  read the same `.vna` column layout.

## Campaign modes (Lab and Field)

`adv::Mode` (`src/core/ProjectSettings.h`) is a **project property**, persisted in
`.advProj` and switched under the *Project* menu.

- **Lab (Vectrino)**, the default: unchanged behaviour, `FlumeView`, flume coordinates.
- **Field (FlowTracker)**: `MapView` with OpenStreetMap tiles, point x-y are easting and
  northing in `ProjectModel::epsg()`, z still means height above the bed.

Things that are easy to get wrong here:

- `FlumeView` stretches its two axes independently (`m_yStretch` plus
  `Qt::IgnoreAspectRatio`) so the channel fills the panel. **`MapView` must never do
  that**: it is conformal by construction, and shearing would misplace everything against
  the basemap.
- The derived TKE series is persisted as the stable id `labels::tkeSeriesId()` (`"@tke"`),
  never as its display name, which depends on the mode. `PlotFrame::restoreState` migrates
  the legacy literal.
- `profileTemplateColumns()` stays mode-independent because it must match
  `tools/make_template.py`; the field caveat goes into the sheet instead.
- Station positions are computed **once per station** in the import wizard. Recomputing per
  point can differ in the last bits, and `xyKey()` formats coordinates to four decimals, so
  one vertical would split into several profiles.

## FlowTracker2 domain knowledge

- `.ft` is a **ZIP archive** (deflate) of `DataFile.json` plus one
  `PointMeasurements/PointMeasurement_<id>.json` per point. Its central directory uses
  zip64 extra fields with `0xFFFFFFFF` sizes but **no EOCD64 record**, which is why Qt's
  private `QZipReader` cannot read it and miniz is vendored instead. `zipArchiveReadsFlowTrackerZip64`
  in the test suite is the gate for that.
- Sampling is 1 to 10 Hz (2 Hz in the reference data), 30 s per point, so ~60 samples.
  Dissipation is structurally not estimable; see `labels::epsEstimable`.
- `DistanceFromBottom` is the z coordinate directly. `Spikes[]` holds the sample indices the
  instrument rejected; the reader writes them as NaN, which is what reproduces the
  instrument's own statistics.
- `SampleStatistics.DespikedVelocity` in `DataFile.json` is the parity reference. Note the
  firmware reports a **sample** standard deviation (ddof = 1) while `SeriesStats::std` is the
  population one (ddof = 0, matching numpy and the predecessor); the test converts rather
  than changing the application convention.
- Correlation is a 0 to 1 score, rescaled to 0 to 100 on read. Observed range is roughly
  5 to 72 with a median near 35, so the Vectrino default threshold of 70 rejects everything.
  Field imports start with the correlation filter off.
- The CSV exports have **language-dependent headers** and are therefore parsed strictly by
  column position. They lack correlation and spike indices and omit bank stations.
- `QFileInfo("x.ft.dat.csv").suffix()` is `"csv"`. Format dispatch must go through
  `formats::byFilePath`, which matches longest file-name endings, not suffixes.

## Coordinate systems

`adv::crs` implements EPSG:4326, 3857, WGS 84/ETRS89 UTM (`326xx`, `327xx`, `258xx`) and
German Gauss-Krueger (`3146x`) with a sixth-order Krueger series, so there is **no PROJ or
GDAL dependency** and the Windows CI build is unaffected. ETRS89 is deliberately treated as
WGS 84. Gauss-Krueger applies one countrywide Helmert shift and is flagged
`crs::isApproximate`. Reference values in the tests came from pyproj.

## OpenStreetMap tile usage

`MapView` must keep honouring the OSMF tile usage policy: an identifying `User-Agent`, at
most a couple of requests in flight, visible tiles only with no prefetching, a disk cache,
a hard stop after 429/418, and the attribution painted in `paintEvent` so it survives into
exported PNGs.

## Built-in examples and the guided tour

*Help* holds the documentation link, the two example loaders and the tour, and it
absorbed the former *About* menu.

- `examples::loadLab` / `loadField` (`src/core/ExampleProject.cpp`) build the demo
  projects from `src/examples.qrc`. The qrc is compiled into **advcore, not the
  app**, so `tst_core` can cover the loaders; a static library only keeps a
  resource initialiser something references, hence the explicit
  `Q_INIT_RESOURCE(examples)`. Never make the examples read `input-data/` at
  runtime: released packages ship the executable alone.
- `captureDocScreenshots` uses `loadLab` for its scene, so the documentation and
  the example cannot drift apart, and the screenshot mode no longer depends on the
  working directory.
- `GuidedTour` is a non-modal `QDockWidget` plus a `TourHighlight` overlay that is
  a child of the **main window**, not of the target, so it can be drawn over the
  views and cannot disturb QCustomPlot's own painting. Steps are rebuilt per mode.

## Cross-platform gotchas

Both platforms are first-class: Linux is the development machine, Windows is where most
users run the release zip. Things that have already gone wrong once:

- **The Qt SQLite driver is a separate Debian/Ubuntu package** (`libqt6sql6-sqlite`) that
  `qt6-base-dev` does *not* pull in. Without it `QSqlDatabase::isDriverAvailable("QSQLITE")`
  is false, GeoPackage import disables itself, and nothing else complains. It is installed
  explicitly in CI and requested by name through `EXTRA_QT_PLUGINS` for the AppImage; the
  workflow's "Verify the AppImage carries the field-mode runtime" step is the gate. Qt's own
  Windows binaries ship the driver inside qtbase, so this bites Linux only.
- **Compare file-name endings case insensitively.** Windows file systems are case
  insensitive, so `.advProj`, `.ft.dat.csv` and friends come back in whatever case they were
  stored with. Conversely, never *rebuild* a sibling file name from a lower-case literal:
  `FlowTrackerCsvReader` keeps the case of the ending it matched and falls back to a
  case-insensitive directory scan, because an upper-case export pair opens fine on Windows
  and not at all on Linux.
- **The window must fit the screen.** `MainWindow` clamps its initial size to
  `availableGeometry()`; the preferred 1280x860 overflows a 1366x768 laptop, and a window
  taller than the display hides the status bar. `captureDocScreenshots` pins 1280x860 back so
  the published screenshots do not vary with the build host's virtual screen.
- **`.gitattributes` protects the fixtures.** A `.ft` archive, a GeoPackage or a `.vna` that
  went through end-of-line conversion is silently corrupt, and the FlowTracker2 CSV exports
  carry a UTF-8 BOM that must survive verbatim. Check with `git check-attr` before adding
  new binary test data.
- Qt 6.2 is the floor, because the AppImage is built on ubuntu-22.04 to keep the glibc
  requirement low. The development machine runs a much newer Qt, so newer APIs compile here
  and break in CI. `M_PI` is only available on MSVC via `<QtMath>`, which every user of it
  includes.
